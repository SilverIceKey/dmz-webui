# nftables 所有权收敛进度

## 当前状态

- 状态：本机端口开放功能与双表大陆白名单实现、本地验证均已完成。
- 当前结论：全局 `flush ruleset` 根因已消除，运行时只替换两个项目独占表。

## 最近关键结论

- 防火墙、SSL、CN IP 和控制台入口均已接入统一定向应用。
- 部署与更新不再重启 nftables。
- 旧版迁移不会扫描或复制 Docker 链中的 DNAT。
- 后端全量单测、前端构建及隔离 nftables 迁移验证通过。
- 已确认 SSL CRUD 存在先写 JSON、后应用运行态的非事务顺序。
- 已确认 Caddy reload 失败会在当前 API 请求内 fallback restart。
- SSL/Caddy/nftables 已改为失败回滚、成功后提交 JSON。
- 普通 NAT 变更只替换 NAT 表，隔离验证确认 filter/input 哨兵保持不变。
- 当前回归测试为 29 项，前端生产构建通过。
- 已用部署同步脚本真实调用复现 `# Portainer}`；同步脚本按 `}` 字符插入且
  未补尾部换行是直接根因。
- 已确认后端删除畸形规则时会把同一行的链闭合括号一并删除，是编辑路径的
  次生故障。
- 普通端口转发、SSL 代理和部署同步现已统一使用公共链插入函数。
- 删除旧规则前会先修复历史畸形闭合括号，新增与编辑均保持 `规则\n}`。
- 生成的端口转发配置已通过本机 `nft -c -f -` 语法检查。
- 本机开放规则直接引用现有 NAT 表 `@cn_ipv4` 时，真实 `nft -c` 报集合不
  存在；已确认 nftables set 不能跨表引用。
- 建议在项目 filter 表增加同名集合，并让 CN 更新与部署同步维护两份元素；
  方案已确认并完成。
- 防火墙页面现可区分“端口转发”和“本机端口开放”，本机开放不要求目标
  IP/端口。
- 新增本机开放 CRUD 接口，规则仅写入带 `local-open` 标记的 input 行。
- 本机开放、端口转发、SSL 代理和固定 input 放行之间增加端口冲突校验。
- 大陆、境外和自定义来源白名单同时适用于本机开放规则。
- filter 与 NAT 表各自维护 `cn_ipv4` 集合；CN 更新与部署同步同时维护两份。
- 当前后端回归测试为 36 项，完整生成配置通过真实 `nft -c -f -`，前端
  生产构建通过。
