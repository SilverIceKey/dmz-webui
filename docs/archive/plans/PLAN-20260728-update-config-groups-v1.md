# 部署更新配置分组确认修复计划

## 当前状态

- 状态：三个配置分组已实现并完成本地回放。
- 确认时间：2026-07-28。

## 问题与根因

当前 `prompt_config` 在加载 `/etc/dmz-webui/install.conf` 后只询问一次：

```text
是否复用？[Y/n]
```

选择复用或直接回车后立即 `return`，导致域名/Caddy、站点标题、页签标题和
备案号全部跳过。为了修改标题而选择不复用，又会进入全部配置重填，并可能因
Caddy 模式默认值与现有值不一致而误改部署模式。

根因是不同职责的配置共享了一个全局提前返回条件，而不是各自确认。

## 建议交互分组

检测到已有配置时取消全局“是否复用”开关，改为三个互不影响的确认点：

1. 公网与 Caddy 配置
   - 公网域名
   - Caddy 标准 443 / 非 443 模式
   - ACME 邮箱或 Cloudflare 证书配置
   - WebUI 后端监听地址
2. 页面标题配置
   - 站点标题
   - 浏览器页签标题
3. 备案配置
   - ICP 备案号

建议提示：

```text
是否修改公网与 Caddy 配置？[y/N]
是否修改页面标题配置？[y/N]
是否修改备案配置？[y/N]
```

每组默认不修改，但无论前一组选择什么，后续两组都必须继续询问，不能提前
结束整个配置流程。

首次部署或没有历史配置时仍按顺序收集全部必需配置。

## 行为约束

- 任一分组选择不修改时，原值必须完整保留。
- 修改 Caddy 分组时，直接回车必须保留当前模式，不能固定默认为非 443。
- 修改标题分组时，回车保留当前值，输入 `-` 恢复 `DMZ WebUI`。
- 修改备案分组时，回车保留当前值，输入 `-` 清空。
- 每次交互结束后统一写回 `install.conf` 和 systemd override。
- 不改变防火墙、证书申请、更新同步和服务重启顺序。

## 验收

- 只修改标题时，域名、Caddy 端口、TLS 模式、后端地址和备案号不变。
- 跳过 Caddy 分组后仍会询问标题和备案分组。
- 跳过标题分组后仍会询问备案分组。
- 只修改备案号时，其他配置不变。
- 修改 Caddy 分组并回车时保留当前标准 443/非 443 模式。
- 无旧配置的首次部署仍能完成全部配置。
- Shell 交互回放、后端全量测试和 `bash -n` 通过。
