# nftables 链闭合括号换行修复计划

> 归档状态：已完成
> 替代文档：`docs/reports/REPORT-20260727-nft-chain-newline-v1.md`
> 归档时间：2026-07-27

## 背景与证据

端口转发新增或编辑后，规则可能被写成：

```nft
ip saddr @cn_ipv4 tcp dport 19262 dnat to 127.0.0.1:19262 # Portainer}
```

已用 `scripts/sync_nftables.py` 的真实调用参数复现。该脚本以链闭合
`}` 字符为插入点，写入内容为 `换行 + 规则 + 原闭合括号`，没有在规则与
闭合括号之间写入换行。

## 根因判断

- 部署同步脚本与后端分别维护了三套链插入实现，换行语义不一致。
- 同步脚本按闭合括号字符插入，直接制造 `规则}`。
- 后端删除规则按整行删除；面对已经畸形的 `规则}` 时，会把链闭合括号一并
  删除，导致编辑流程无法重新找到链结尾。

## 范围

- 在防火墙公共模块集中实现命名链闭合括号规范化和规则插入。
- 新增、编辑、SSL 代理规则生成及部署同步统一调用公共实现。
- 自动修复由旧实现产生的“规则与链闭合括号同一行”配置。
- 保持现有 API、字段、调用顺序、防火墙表所有权和事务边界不变。
- 不调整前端交互，不修改非本项目 nftables 对象。

## 实施步骤

1. 为公共换行与插入行为补充回归测试，覆盖正常配置和历史畸形配置。
2. 在 `backend/firewall.py` 实现公共链编辑函数。
3. 替换后端普通端口转发、SSL 规则和部署同步脚本的重复插入逻辑。
4. 在删除规则前规范化闭合括号，保证编辑历史畸形规则时不会删除括号。
5. 执行后端全量单测、Python 编译检查、脚本语法检查和差异检查。
6. 更新进度、交接上下文和缺陷报告；完成后归档本计划。

## 验收标准

- 新增规则后必须形成 `规则行 + 换行 + 独立闭合括号行`。
- 编辑旧的 `# 注释}` 畸形规则后，链闭合括号仍存在且独占一行。
- SSL 代理和部署同步写入遵守相同格式。
- 生成配置能够通过现有所有权解析和 nftables 检查链路。
- 后端全量单测通过，且新增用例能在旧实现上稳定失败。

## 风险与回滚

- 风险：规则注释中人为包含花括号时，原始字符扫描可能误判。
- 约束：修复仅作用于明确命名的项目链，并使用嵌套深度匹配。
- 回滚：回退公共函数及调用点即可；配置写入仍受现有检查、运行态应用和
  原子持久化保护。
