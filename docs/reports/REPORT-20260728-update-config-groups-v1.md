# 部署更新配置分组确认修复报告

## 背景

动态标题上线后，用户运行 `update.sh` 没有看到标题输入。排查发现
`prompt_config` 在“是否复用？[Y/n]”选择默认复用时直接返回，域名/Caddy、
标题和备案全部被跳过；选择不复用又会要求重填全部配置。

## 根因与证据

根因是不同职责的配置共享一个全局提前返回条件：

```text
load_config
  -> 是否复用
  -> Yes: return
  -> No: 重填全部配置
```

标题提示位于该 `return` 之后，因此默认复用必然无法修改标题。进一步检查
发现，重填 Caddy 配置时模式默认值固定为非 443，即使现有配置是标准 443，
直接回车也可能意外改变部署模式。

## 修复范围

将配置拆成三个独立分组：

1. 公网与 Caddy
2. 页面标题
3. 备案

已有配置时每组分别确认；前一组选择不修改不会跳过后一组。没有历史配置时
仍收集全部配置。

Caddy 模式提示根据当前 `CADDY_MODE` 计算默认选项，ACME 邮箱也保留当前值。
本轮没有改变证书申请、防火墙、代码同步或服务重启顺序。

## 结论

全局复用开关的错误控制范围已消除。用户可以只修改标题而保留公网、Caddy
和备案配置，也可以独立修改其他分组。

## 剩余风险

- 正在执行的旧版更新脚本不会在运行中自动获得新交互逻辑。完成代码更新后
  必须重新运行最新版 `update.sh`。
